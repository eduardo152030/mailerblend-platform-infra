   Guardar también target/inventario/reglas vigentes y registry para rollback coherente.
   Estos backups de R1 **todavía no se han creado**.

   comprobar que el cgroup namespace del nuevo cAdvisor coincide con el del CT y
   no con PVE; detenerse si no se demuestra ese límite.
   No crear rutas ausentes.
4. Aplicar solo exporters con helper scoped 613, ambas opciones CPU/socket, parada
   ordenada sin SIGKILL. Conservar originales como *-pre-phase4-613; no rm/down/prune.
5. Verificar inmediatamente fuente/capacidad/ct_id y RAM contra PVE, modelo/imagen y
   métricas Docker de ambos exporters. Registrar evidencia puntual CPU; promover
   solo 613 en registry/candidato incremental, sin marcar estabilidad DONE todavía.
6. Aplicar y verificar integración por APIs; no continuar diez minutos sin reglas.
   lxc:cpu_usage:percent válido único, viejo contador ausente, sin duplicados/errores,

   revertir solo 613 a legacy unverified. Verificar, reanudar mismos candidatos,
   integrar de nuevo y realizar **>=600s / >=21 muestras integradas** finales.
8. Prueba final de regla controlada FIRING/RESOLVED desde datos reales, recibida en
   Telegram durante observación integrada; después segunda aplicación conserva IDs/StartedAt y no recrea exporters. Segunda aplicación
   de integración con hashes iguales no escribe/recarga. Cero OOM nuevos desde
   preflight, sin presión significativa, recursos dentro de cuotas y >=64 MiB de
